Why this fork exists

The official package needs macOS 13+. This one doesn't.

Clovercut's released macOS build is produced on much newer systems: its bundled FFmpeg calls VideoToolbox symbols from macOS 13, ONNX Runtime and libplacebo call std::__1::to_chars floating-point symbols that only exist in the macOS 13.3 libc++, and sherpa-onnx calls an Accelerate entry point from the same release. On Monterey the app either fails to launch or silently disables every AI feature. Studio Inspirasi ships a compatibility shim that supplies those symbols, so nothing has to be turned off.

Install

Three steps and it opens.

Download Studio-Inspirasi-0.1.9-macos-x86_64.dmg and drag the app to Applications.

Open it once the Gatekeeper way: the build is ad-hoc signed, so right-click the app → Open (or approve it in System Settings → Privacy & Security). Every launch after that is normal.

Edit. Existing Clovercut settings and downloaded models are migrated automatically on first launch.

Building it yourself on Monterey? docs/BUILDING-macOS12.md has the one-command script — it applies the brand overlay, compiles with AVX2, patches every bundled dylib to a 12.0 floor, signs and smoke-tests the bundle.

Kept in step with upstream

New Clovercut releases land here too.

The fork tracks tulcoturo/clovercut as a git upstream. Branding is an idempotent overlay, not a divergent edit, so merging upstream stays clean — one script fetches, merges, re-applies the brand and the Monterey patches, rebuilds and smoke-tests.

git fetch upstream→ merge upstream/main→ apply-brand.py→ build + smoke
